# Borealos「视频说话声提取」设计规格

## 1. 决策与范围

“视频说话声提取”是 Borealos 的正式新功能，首发入口、任务管理、结果管理、权限与计费提示均归属 Borealos。AI 影视助手不是首发承载方；未来只能通过稳定的任务接口复用该能力，不直接依赖 Borealos 页面或内部文件路径。

本规格只定义产品与技术设计，不实施代码、模型安装、下载或部署。

### 1.1 目标

用户上传单个或一批视频/音频后，系统以本地模型优先的方式协同使用 RoFormer、Demucs、ClearerVoice、Qwen3-ASR、Qwen Omni 和 Whisper，生成：

- 纯人声；
- 增强人声；
- 带时间戳的完整逐字稿；
- 说话人分段；
- SRT、ASS、VTT 字幕；
- 摘要与章节；
- 可追溯的可信度报告。

任务必须支持批量全量处理、真实进度、暂停、恢复、失败重试和服务重启后的断点续跑。任何云端调用前必须先展示费用预估并获得用户明确确认。

### 1.2 非目标

- 不在首版提供视频编辑、口型同步、配音生成或影视成片功能。
- 不承诺从任意混音中得到录音棚级完全无损干声；结果必须通过可信度报告表达局限。
- 不以单一模型替代六模型协同，也不把“模型已安装”伪装为“模型已运行”。
- 不在本规格中确定某一家云厂商为永久唯一供应商。
- 不让浏览器承担长时模型推理，也不把大文件或模型结果放入 Git 仓库。

## 2. 现状与方案选择

现有 Borealos 采用同一 Web 产品承载浏览器及 Windows、macOS、Android 外壳，Web 服务已具有用户目录隔离、异步任务、工作文件持久化、重启恢复和灵动岛任务映射。现有 `server.js` 同时承载较多业务，不适合继续内嵌 GPU 模型生命周期。

考虑过三种方式：

1. **全部写进现有 Node Web 服务**：接线最快，但 Python 音频生态、GPU 显存回收、长任务隔离和未来复用都很差，不采用。
2. **每个模型单独成为微服务**：隔离最强，但首版部署、端口、监控和版本协调成本过高，不采用。
3. **Borealos 编排层 + 单一语音工作进程 + 模型适配器（采用）**：Web 服务负责认证、任务、费用确认和下载；本地语音工作进程负责媒体处理与六模型编排；每个模型通过适配器隔离。将来可在不改变外部任务契约的情况下拆分工作进程。

## 3. 产品体验

### 3.1 入口与任务创建

在 Borealos 工具区增加“视频说话声提取”。创建页分为四块：

1. **选择文件**：拖入一个或多个视频/音频；展示文件名、时长、大小、音轨和格式。支持选择用户已有视频。文件列表默认全选，用户可移除单项。
2. **输出选择**：默认勾选纯人声、增强人声、逐字稿、说话人分段、三种字幕、摘要章节和可信度报告。用户可以取消不需要的交付物，但“可信度报告”始终生成。
3. **处理策略**：
   - 自动（推荐）：本地全模型协同，本地能力不足时停在费用确认；
   - 仅本地：不允许云端，无法完成的输出标记为降级；
   - 允许云端候选：仍须逐次费用确认，不代表预授权扣费。
4. **语言与说话人**：语言默认自动识别；可指定语言；说话人数默认自动，也可设范围。用户可填写术语、人名和品牌词表。

创建前显示本地可用性检查：模型状态、预计磁盘临时空间、是否检测到可用 GPU、预计耗时区间。耗时只是预测，不能作为任务进度。

### 3.2 任务中心

批量任务由一个 `batch` 和多个 `item` 构成。页面同时展示：

- 批次：总文件、已完成、处理中、失败、暂停及总进度；
- 单文件：当前阶段、阶段内真实计数、已耗时、所用执行位置（本地/云端）；
- 当前模型与动作，例如“RoFormer 分离 3/12 个音频块”；
- 暂停、恢复、重试失败项、取消未开始项；
- 单项结果预览和“下载全部结果”。

“全量处理”表示列表中每一个有效输入都形成明确终态：`completed`、`completed_with_warnings`、`failed` 或 `cancelled`。不得因为前 N 个成功而把批次标为完成。

### 3.3 结果页

结果页提供：

- 原音轨、纯人声、增强人声的波形对比试听；
- 逐字稿与视频时间联动，点击文字跳转；
- 说话人标签重命名，重命名同步更新逐字稿与字幕；
- 字幕样式预览（ASS）及三种字幕下载；
- 摘要、章节、关键点；
- 可信度报告，突出低可信片段、重叠说话、强噪声、可能被分离损伤的片段；
- 单文件下载或批次 ZIP 清单下载。

说话人标签默认使用“说话人 1、说话人 2”，不得根据声音猜测真实身份。用户重命名仅影响展示层和导出文件，不重新推理。

## 4. 六模型协同

六个模型全部纳入正式流水线，但不是对每一秒内容无条件重复运行。编排器依据输入质量、模型可用性和中间质量指标决定分支，并在任务清单中记录实际执行证据。

| 模型 | 首要职责 | 协同与回退 |
| --- | --- | --- |
| RoFormer | 音乐/伴奏与语音的主分离器，生成候选纯人声 | 与 Demucs 候选按无参考质量指标和抽样复核比较；失败则由 Demucs 单独完成 |
| Demucs | 第二路源分离、复杂混音交叉验证 | RoFormer 输出出现残留音乐、相位破坏或削声时提供替代/融合候选 |
| ClearerVoice | 去噪、去混响、语音增强 | 对选中的纯人声做增强；原始纯人声仍保留，避免不可逆覆盖 |
| Qwen3-ASR | 本地首选中文/多语逐字识别与词级时间信息 | 与 Whisper 的高风险片段复核结果融合 |
| Whisper | 独立转写基线、语言检测和低可信片段复核 | Qwen3-ASR 不可用时成为主转写；两者冲突进入可信度报告 |
| Qwen Omni | 语义校正、说话人上下文辅助、摘要与章节 | 不得凭语义改写逐字稿事实；校正必须保留原识别候选与变更记录 |

### 4.1 推荐流水线

1. **媒体探测**：FFprobe 读取容器、音轨、时长、采样率和声道；音频标准化为内部无损格式。
2. **切块与活动检测**：按可恢复边界切块，保留重叠上下文；静音块跳过重模型但计入完成计数。
3. **双路分离**：RoFormer 与 Demucs 生成候选。资源紧张时先运行 RoFormer，只有质量门失败的块再运行 Demucs；此时 Demucs 仍已纳入协同并产生实际决策记录。
4. **候选选择/融合**：依据语音保持度、非语音残留、削波、能量连续性和 ASR 可懂度评分选择，不允许仅按文件大小判断。
5. **增强**：ClearerVoice 对选中纯人声处理，分别保存 `voice_clean` 与 `voice_enhanced`。
6. **双 ASR**：Qwen3-ASR 作为本地主路；Whisper 生成独立基线。低可信、专名、数字、语言切换和两模型不一致片段进入二次复核。
7. **说话人分段**：由独立的说话人嵌入/聚类能力完成时间段聚类，Qwen Omni 只做上下文辅助合并与标签一致性检查。六个指定模型不应被虚假描述为专用 diarization 模型；实现计划必须选定可本地部署的说话人分段组件。
8. **语义整理**：Qwen Omni 生成摘要、章节、标点与谨慎的文本校正。所有校正保存来源和理由，逐字层不得删除口误，另提供“易读稿”视图。
9. **导出与质检**：生成音频、JSON 主记录、TXT/Markdown、SRT/ASS/VTT 和可信度 HTML/JSON；校验时码单调、文件可解码、字幕不越界、交付物齐全。

### 4.2 模型执行原则

- 本地模型优先级高于所有云端候选。
- 一个模型不可用时，任务可以降级，但结果清单必须标记“未运行”及原因。
- “六模型协同”验收以编排器具有六个正式适配器、决策规则及执行审计为准；不得伪造每个模型都成功执行。
- GPU 推理默认串行复用模型，按显存预算卸载；CPU 密集步骤可有限并行。并发数由工作进程基于硬件探测确定，而不是前端写死。
- 每个模型版本、权重摘要、参数、设备、开始/结束时间和退出状态写入 `provenance`。

## 5. 架构与边界

```text
Borealos Web / Windows / macOS / Android
       |
       | 鉴权后的 /api/speech-extraction/*
       v
Borealos Web 服务（控制平面）
  - 上传与用户隔离
  - 批次/任务状态
  - 本地能力与费用确认
  - 灵动岛投影
  - 下载与保留策略
       |
       | 本机私有任务协议
       v
Speech Worker（执行平面）
  - FFmpeg/FFprobe
  - Pipeline Orchestrator
  - Model Adapters（六模型）
  - Checkpoints / Quality Gates
  - Exporters
       |
       +--> 本地模型（默认）
       +--> Cloud Adapter（费用批准后）
```

控制平面是唯一对客户端开放的接口。Speech Worker 不接受公网请求，不信任前端给出的用户目录，不保存云密钥到任务文件。影视助手未来调用稳定的服务契约或独立部署同一 Worker，不读取 Borealos 内部状态文件。

### 5.1 建议代码边界（供后续实施计划使用）

- `apps/web`：页面、API、认证、任务投影、结果下载；
- `services/speech-worker`：Python 工作进程与模型适配器；
- `services/speech-worker/contracts`：任务、进度、结果、费用候选的版本化结构；
- 用户运行数据：`D:\KIMI\work-users\<用户名>\speech-extraction\`，不进入源码目录。

不得在设计阶段创建上述实现目录。

## 6. 数据与持久化

### 6.1 目录

每个用户的任务使用不可猜测的批次和项目标识：

```text
speech-extraction/
  batches/<batchId>/batch.json
  jobs/<jobId>/
    job.json
    input/source.<ext>
    checkpoints/
    intermediates/
    outputs/
    logs/events.jsonl
```

下载 API 通过任务归属和允许的相对路径解析文件；拒绝绝对路径、`..` 和软链接越界。

### 6.2 批次状态

```json
{
  "schemaVersion": 1,
  "batchId": "seb_...",
  "ownerId": "internal-user-id",
  "status": "running",
  "jobIds": ["sej_..."],
  "counts": {"total": 3, "completed": 1, "warnings": 0, "failed": 0, "paused": 0},
  "progress": {"mode": "determinate", "completedUnits": 481, "totalUnits": 1200, "percent": 40.08},
  "createdAt": "ISO-8601",
  "updatedAt": "ISO-8601"
}
```

### 6.3 单项状态

`status` 仅取：

`queued | waiting_for_cost_approval | running | pausing | paused | retrying | completed | completed_with_warnings | failed | cancelling | cancelled`

关键字段包括：

- 输入指纹、媒体元数据和选择的输出；
- `stage`、`completedUnits`、`totalUnits`、`currentItemLabel`；
- `attempt`、`retryOf`、最近错误及可重试性；
- `pauseRequestedAt`、`checkpointId`；
- `costEstimate`、`costApproval` 和实际云端用量；
- 每个阶段、块、模型和导出物状态；
- `provenance` 与质量指标；
- 输出清单（相对路径、大小、SHA-256、MIME）。

所有状态写入采用临时文件加原子替换；事件追加写入 `events.jsonl`。任务更新带递增 `revision`，避免重复轮询或恢复进程覆盖新状态。

## 7. 真实进度、暂停与恢复

### 7.1 进度原则

进度来自已完成的可计数工作单元，不按定时器增长，不使用“模型通常需要多久”伪造百分比。

创建任务并完成媒体探测后，系统知道时长、块数和所需输出，形成阶段工作量。建议默认权重：

| 阶段 | 工作量占比 | 真实计数 |
| --- | ---: | --- |
| 探测/标准化/切块 | 5% | 已完成文件、音轨和块 |
| 分离（RoFormer/Demucs） | 35% | 已完成的模型-块单位 |
| ClearerVoice 增强 | 15% | 已增强块 |
| Qwen3-ASR/Whisper | 25% | 已转写的模型-音频秒或块 |
| 说话人分段 | 8% | 已处理音频秒 |
| Qwen Omni 摘要章节 | 5% | 已完成语义批次 |
| 导出与质检 | 7% | 已校验交付物 |

权重会依据用户取消的输出和实际启用的回退分支重新归一化。动态增加 Demucs 复核任务时同时增加 `totalUnits`；百分比允许小幅回退，但事件中必须说明“新增质量复核”，不得锁死旧分母。未知总量时返回 `mode: indeterminate` 和真实计数，不显示假百分比。最终质检前最多显示 99%，只有所有必需交付物通过校验才到 100%。

批次进度按各文件估算音频秒与实际模型工作量加权，不能让一个 5 秒文件和一个 2 小时文件各占 50%。

### 7.2 灵动岛

任务类型固定为 `speech-extraction`，页面与灵动岛读取同一服务端状态：

- 单任务时显示阶段、文件名短名和真实百分比；
- 多任务时聚合为“说话声提取 X/Y”，进度使用批次加权值；
- `waiting_for_cost_approval` 显示“等待确认云端费用”，不继续增长；
- 暂停显示“已暂停”，失败保留可重试入口；
- 刷新、换页和客户端重启后由活动任务 API 恢复；
- 网络暂时失败不把后台任务标为失败。

### 7.3 暂停/恢复

暂停是协作式暂停：

1. API 写入 `pauseRequested`，状态变为 `pausing`；
2. Worker 在最近的安全边界（一个块或一次模型调用结束）落盘检查点；
3. 释放可释放的 GPU 资源后变为 `paused`；
4. 恢复从最后一个完整检查点继续，未完成的块重新运行；
5. 已校验的中间产物按输入指纹、模型版本和参数摘要复用。

不得通过强杀进程宣称“已安全暂停”。云端请求若已经提交，暂停只能停止后续请求；已产生的费用和远端状态继续记录。

### 7.4 重试

- 单块瞬时故障：指数退避自动重试最多 2 次；
- GPU 显存不足：降低并发/卸载模型后重试 1 次；
- 确定性输入或格式错误：不自动重试；
- 用户“重试失败项”生成新 `attempt`，复用已校验检查点；
- 模型版本或关键参数改变时，与其相关的检查点失效；
- 批次中一个文件失败不阻塞其他文件。

## 8. 本地优先与云端费用门

### 8.1 本地能力判定

Worker 启动时报告每个模型：

`available | downloading | unavailable | unhealthy`

并附版本、设备、估算显存/内存和最近自检时间。任务编排必须先尝试满足质量和输出要求的本地路径。缺模型、硬件不足、模型崩溃或本地质量门未通过时，只能生成云端候选，不得自动调用。

### 8.2 费用预估对象

费用估算必须包括：

- 供应商、模型、计价单位和价格版本/获取时间；
- 待处理音频秒数、输入/输出 token 或其他计费量；
- 单项费用、批次总费用、币种；
- 税费或汇率是否包含；
- 最小值、最大值和产生区间的原因；
- 预估有效期；
- 本地降级方案及其缺失输出。

价格缓存过期或无法取得准确计价时，不允许显示 `¥0`；状态标为“暂无法准确估价”，云端按钮禁用。

### 8.3 明确批准

前端提交 `estimateId`、批准上限和一次性确认。服务端验证估算属于当前用户、任务和未过期版本，写入不可变审计事件后才可向云端发请求。批准只覆盖该估算列出的阶段与上限；重试、换供应商或预计超上限必须再次确认。后端在每次云调用前检查剩余额度。取消批准不撤销已产生费用。

实际费用能获取时写入结果；只能估算时明确标记为估算，不伪装成账单。

## 9. API 契约

所有接口要求现有 Borealos 会话鉴权，并校验资源归属。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/speech-extraction/capabilities` | 本地模型、硬件、可用输出及云端供应商状态 |
| `POST /api/speech-extraction/uploads` | 分块上传并返回受控上传标识 |
| `POST /api/speech-extraction/batches` | 创建批次及单项任务 |
| `GET /api/speech-extraction/batches/:batchId` | 批次状态与聚合进度 |
| `GET /api/speech-extraction/jobs/:jobId` | 单项状态、阶段、警告和结果 |
| `GET /api/speech-extraction/active` | 页面/灵动岛恢复当前用户活动任务 |
| `POST /api/speech-extraction/jobs/:jobId/pause` | 请求安全暂停 |
| `POST /api/speech-extraction/jobs/:jobId/resume` | 从检查点恢复 |
| `POST /api/speech-extraction/jobs/:jobId/retry` | 新 attempt 重试失败项 |
| `POST /api/speech-extraction/jobs/:jobId/cancel` | 取消未开始工作并清理运行资源 |
| `POST /api/speech-extraction/jobs/:jobId/cost-estimates` | 创建当前云端候选费用估算 |
| `POST /api/speech-extraction/jobs/:jobId/cost-approvals` | 对未过期估算作一次明确批准 |
| `GET /api/speech-extraction/jobs/:jobId/artifacts/:artifactId` | 鉴权下载单项交付物 |
| `POST /api/speech-extraction/batches/:batchId/archive` | 异步生成带 manifest 的 ZIP |

写操作接受 `Idempotency-Key`。状态响应含 `revision`、`updatedAt` 和 `nextPollAfterMs`。第一版可沿用轮询；未来可增加 SSE，但不能因此建立第二套状态源。

## 10. 输出契约

每个成功或带警告完成的任务至少包含：

- `voice_clean.wav`：选定的纯人声，无损 PCM；
- `voice_enhanced.wav`：ClearerVoice 增强结果；
- `transcript.json`：权威机器可读记录；
- `transcript.txt`：完整逐字稿；
- `readable-transcript.md`：不改变事实的易读稿；
- `subtitles.srt`、`subtitles.ass`、`subtitles.vtt`；
- `summary.md`：摘要、关键点和章节；
- `confidence-report.json` 与 `confidence-report.html`；
- `manifest.json`：输出摘要、校验和、模型来源和警告。

`transcript.json` 的层级为 `document -> speakers -> segments -> words`。每个 word 至少包含 `text`、`startMs`、`endMs`、`speakerId`、`confidence`、`asrSources`；segment 还包含语言、重叠说话标记、原候选、采用文本及校正历史。无法得到可靠词级时码时可使用 segment 时码，但必须在能力和可信度字段中声明，不能均匀伪造逐词时间。

字幕要求：

- 时码非负、单调且不超过媒体时长；
- 默认每条最多两行，中文行宽和最短显示时间由导出器配置；
- 重叠说话在 ASS 使用独立样式/位置，SRT/VTT 使用明确说话人前缀；
- 用户重命名说话人后可无推理重新导出；
- UTF-8 编码，ASS 使用内置安全字体回退声明。

## 11. 可信度报告

报告不是单个虚假“准确率”，而是可解释的多维证据：

- **分离质量**：语音保持、音乐/噪声残留、削波、断裂、RoFormer/Demucs 一致性；
- **增强质量**：增强前后可懂度变化、过度降噪风险；
- **转写可信度**：Qwen3-ASR/Whisper 一致性、模型置信度、语言切换、专名/数字风险；
- **说话人可信度**：聚类边界稳定度、重叠说话、短片段和可能的错并/错分；
- **语义处理证据**：Qwen Omni 改动了哪些文本、依据和原候选；
- **覆盖率**：有效语音秒、已转写秒、低可信秒、未处理秒；
- **执行完整性**：六模型各自为 `ran | skipped_by_rule | unavailable | failed | cloud_declined`，并说明原因。

每个片段使用 `high | medium | low | unknown` 等级并附原因码。总体等级按最弱关键维度和低可信时长占比生成，不能把不同模型的未校准分数直接平均成“准确率 97%”。报告明确提示用户复核低可信片段。

## 12. 错误、降级与资源控制

- 无音轨：该文件失败并给出明确原因，批次继续。
- 多音轨：默认处理用户选择的音轨；未选择时优先语言/默认音轨并记录决策。
- 损坏或不支持格式：探测阶段失败，不进入模型。
- 没有可检测语音：输出空逐字稿和检测报告，状态为 `completed_with_warnings`。
- 某个分离器失败：使用另一候选并标警告；两者均失败则该文件失败。
- ClearerVoice 失败：保留纯人声，增强人声缺失，带警告完成。
- 一路 ASR 失败：另一路继续，可信度降级；两路均失败则字幕/逐字稿失败，音频仍可作为部分结果保留，任务标记失败并列出可下载产物。
- Qwen Omni 不可用且用户拒绝云端：逐字稿和字幕仍完成，摘要章节标记缺失，带警告完成。
- 磁盘不足：创建前阻止；运行中进入可恢复失败，保留已完成检查点。
- Worker 心跳超时：控制平面标记 `worker_unreachable`，不立即覆盖为永久失败；恢复后按租约与检查点接管。

每个运行项使用租约，防止服务重启或多 Worker 重复执行。中间文件有引用计数，只有终态且超过保留期后才清理。用户可提前删除任务；删除是独立的明确操作，不与“取消”混同。

## 13. 安全、隐私与多用户

- 所有任务、文件、估算、批准和下载都必须按内部用户 ID 隔离，显示名不作为目录信任边界。
- 上传限制扩展名、MIME、探测结果、单文件大小、批次总量和用户配额；文件名仅作展示。
- Worker 接收受控任务标识，不接受客户端任意本机路径或任意命令参数。
- FFmpeg 参数使用数组调用，字幕文本和文件名不参与 shell 拼接。
- 云端传输前明确展示会发送的内容、供应商和隐私提示；默认只发送必要音频块/文本。
- 日志不得记录音频内容、完整逐字稿、访问令牌或云密钥。
- 任务删除时清除输入、中间件、输出和可识别文本，并留下不含内容的审计结果。
- 默认保留期限在实施前与 Borealos 当前用户数据政策统一；UI 必须显示实际期限，不能在规格中虚构天数。

## 14. 可观测性

记录但不暴露敏感内容：

- 排队时长、各阶段耗时、实时处理倍速；
- CPU/GPU/显存峰值、模型加载和卸载；
- 每模型成功率、降级率、OOM 和重试；
- 云端估算、批准上限、实际可得费用；
- 各输出覆盖率与低可信时长；
- Worker 心跳、租约和检查点恢复次数。

用户日志使用易读阶段与错误建议；诊断日志使用关联 ID：`batchId`、`jobId`、`attempt`、`stageRunId`，但不返回其他用户信息。

## 15. 验收标准

### 15.1 功能

1. 单文件产生所有九类约定结果，音频可播放、字幕可解析、逐字稿可时间联动。
2. 至少三文件批次全量运行，一个文件失败不阻塞另外两个；批次计数与终态准确。
3. RoFormer、Demucs、ClearerVoice、Qwen3-ASR、Qwen Omni、Whisper 均有真实适配器、运行证据和明确回退规则。
4. 暂停在安全边界落检查点；恢复不重复已校验阶段；服务重启后同一任务 ID 可继续。
5. 可对失败项重试，attempt 可追溯，不覆盖旧错误。
6. 云端候选在批准前没有任何供应商请求；过期估算、超上限和跨用户批准均被拒绝。

### 15.2 进度

1. 进度只随真实工作单元完成变化；停止 Worker 后百分比不自行增长。
2. 新增质量复核导致总量变化时显示原因；最终质检前不出现 100%。
3. 页面、任务接口和灵动岛的状态、百分比和终态一致。
4. 刷新、换页、Windows/macOS/Android 外壳重启后能恢复活动任务显示。

### 15.3 质量与兼容

测试集至少覆盖：清晰单人、双人对话、重叠说话、强背景音乐、强噪声、多语言、长视频、无语音、多音轨、损坏媒体。验收比较原音轨、两路分离候选、增强结果和双 ASR 差异；低可信区域必须出现在报告中。

回归验证现有登录、上传、视频生成、亚马逊报告、全局灵动岛、Windows/macOS/Android 外壳不被破坏。大型模型不进入客户端安装包；没有本地 Worker 的远端客户端仍能通过 Borealos 控制平面查看任务和下载结果。

## 16. 实施拆分建议

该功能规模较大，后续应拆成可独立验收的实施计划，而不是一次大提交：

1. 版本化契约、持久任务、租约、真实进度与灵动岛；
2. 上传、媒体探测、切块、检查点和音频导出；
3. RoFormer、Demucs、ClearerVoice 适配与质量门；
4. Qwen3-ASR、Whisper、说话人分段与字幕；
5. Qwen Omni 摘要章节、可信度报告与校正审计；
6. 本地能力检测、云端费用估算/批准门；
7. 批量、结果体验、资源治理、跨端与生产回归。

每一阶段都必须有测试夹具和真实状态验证；不得等到第七阶段才补进度、恢复或用户隔离。

## 17. 已明确的设计结论

- 功能归属 Borealos，影视助手仅在未来复用稳定能力。
- 采用控制平面与语音工作进程分离的架构。
- 六个指定模型全部进入正式编排和审计。
- 说话人分段需要独立专用组件，不能错误宣称六个指定模型已完整覆盖该能力。
- 本地优先是服务端强制规则；云端费用确认是不可绕过的后端门。
- 进度、暂停、恢复和重试均以持久检查点与真实工作单元为基础。
- 逐字稿原文、易读稿和语义校正记录分离，避免模型无痕改写。
