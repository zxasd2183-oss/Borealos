# 亚马逊报告库与重复分析设计

## 目标

在现有亚马逊全量分析功能上增加持久化报告库。用户上传一次报告后，可以反复重新分析；每次分析形成独立、可追溯的版本，旧结果不被覆盖。

报告库支持所有当前可解析的亚马逊 CSV、XLSX、XLS 报告，不局限于广告报告。未知但合法的亚马逊报告仍可归档；解析器不能识别时显示归纳说明和诊断信息，不阻止用户保存文件。

## 用户体验

### 报告库列表

亚马逊分析页面新增“报告库”区域。每张报告卡片展示：

- 文件名和识别出的报告类型
- 上传时间、数据时间范围、总行数
- 文件大小和内容指纹的短标识
- 最近一次分析的状态、时间和摘要
- 成功分析次数及全部版本数
- 查看详情、重新分析和更多操作

列表支持按文件名、报告类型、日期和状态筛选，默认按最近活动时间排序。

### 上传与去重

上传后先计算文件内容指纹。相同用户下存在完全相同的文件时，不再静默保存第二份副本，而是提示：

1. 打开已有报告并重新分析；
2. 作为新的报告条目保存。

第二种选择仍复用底层原文件对象，仅创建新的逻辑报告记录，避免浪费空间。

不同用户之间不进行可观察的去重，也不得通过错误信息、标识或耗时推断另一用户的数据。

### 报告详情

详情页分为：

- 原报告：文件信息、识别类型、数据范围、字段摘要和下载原文件；
- 分析版本：按时间倒序显示全部分析记录；
- 版本对比：选择两个成功版本进行并排比较。

每个分析版本展示：

- 创建时间、完成时间、状态和真实处理进度
- 分析引擎版本、本地或云端模型标识
- 总览结论、关键问题和逐步操作建议
- 全量数据附录和覆盖率
- PDF 及其他已生成产物
- 失败时的通俗错误说明和可重试入口

### 重新分析

“重新分析”直接读取报告库中的原文件，创建新的分析版本和新的后台任务，不要求再次上传。

重新分析可以使用当前默认分析配置，后续可扩展模型和分析模板选择。首版不允许修改原始数据，保证不同版本可比较。

旧成功版本始终可查看。新版本失败、取消或服务重启，不会覆盖或隐藏旧成功结果。

### 版本对比

首版支持选择两个成功版本，对比：

- 核心指标及变化幅度
- 诊断结论的新增、消失和变化
- 优先行动建议的新增、删除和顺序变化
- 分析引擎、模型和生成时间

全量明细不复制到对比页；用户可从变化项跳转到对应版本的完整附录。

## 数据模型

### ReportSource

表示不可变的原始文件对象：

- `sourceId`
- `ownerUserId`
- `sha256`
- `storedPath`
- `originalName`
- `mimeType`
- `sizeBytes`
- `createdAt`

`storedPath` 只在服务端保存，任何 API 均不得返回绝对路径。

### Report

表示用户看到的报告条目：

- `reportId`
- `ownerUserId`
- `sourceId`
- `displayName`
- `reportType`
- `dataRange`
- `rowCount`
- `createdAt`
- `updatedAt`
- `archivedAt`

一个原文件对象可以对应同一用户下多个逻辑报告条目。

### AnalysisVersion

表示一次不可变的分析尝试：

- `versionId`
- `reportId`
- `ownerUserId`
- `taskId`
- `status`
- `analysisEngineVersion`
- `modelProvider`
- `modelName`
- `startedAt`
- `completedAt`
- `summary`
- `resultRef`
- `artifactRefs`
- `errorCode`
- `errorMessage`

版本结果和产物采用版本目录保存。成功版本完成后不再原位修改；重新生成 PDF 产生新的产物修订记录。

## 服务端接口

- `GET /api/amazon/library`：分页、筛选和排序报告列表
- `POST /api/amazon/library/upload`：上传、计算指纹并返回去重决策
- `POST /api/amazon/library/upload/resolve`：打开已有报告或创建新逻辑条目
- `GET /api/amazon/library/:reportId`：报告详情及版本摘要
- `POST /api/amazon/library/:reportId/analyze`：创建新的分析版本
- `GET /api/amazon/library/:reportId/versions/:versionId`：读取完整版本
- `GET /api/amazon/library/:reportId/compare?left=&right=`：比较两个成功版本
- `POST /api/amazon/library/:reportId/versions/:versionId/pdf`：重新生成 PDF
- `DELETE /api/amazon/library/:reportId/versions/:versionId`：删除单个版本
- `DELETE /api/amazon/library/:reportId`：二次确认后归档报告

所有接口首先从登录态取得用户身份，服务端不得接受客户端传入的用户目录或所有者身份。

## 与现有分析流程的关系

现有解析、全量批次、AI 汇总、本地回退、PDF 和任务恢复逻辑继续复用。上传分析改为：

1. 保存或复用 `ReportSource`；
2. 创建 `Report`；
3. 创建 `AnalysisVersion`；
4. 创建全局任务中心任务并把 `taskId` 写入版本；
5. 运行现有分析流水线；
6. 将结果和产物写入版本目录；
7. 原子更新版本终态。

旧接口保留兼容层，但内部转发到报告库服务。前端完成迁移后不再建立孤立于报告库的分析记录。

## 真实进度与灵动岛

每次新分析和重新分析都是独立的全局任务：

- 标题包含报告显示名称
- 阶段包括保存、解析、全量批次、汇总、生成报告和完成
- 批次阶段显示真实已处理数和总数
- 无法精确量化的阶段使用不确定进度，不模拟百分比
- 支持已有流水线能够安全提供的取消、恢复和重试能力

报告库卡片和灵动岛读取同一个服务端任务状态。

## 删除与恢复

- 删除版本默认移入报告级回收区，不立即清除文件。
- 删除报告默认归档；原文件和版本在保留期内可恢复。
- 原文件仍被其他逻辑报告引用时不得清除。
- 永久清除不属于首版自动操作，必须由用户明确确认。

## 错误处理

- 上传中断不会创建可见的半成品报告。
- 文件保存成功但报告记录失败时，后台清理无引用原文件。
- 分析失败保留版本、错误分类和重试入口。
- 服务重启后，运行中的版本由任务恢复机制接管。
- 产物生成失败不丢失已完成的结构化分析结果。
- 云端模型不可用时沿用现有本地全量摘要回退，并清楚标注。

## 测试与验收

必须覆盖：

- 同用户相同文件去重与“另存为新报告”
- 两个用户的文件、报告和版本完全隔离
- 同一报告连续成功分析多次，历史版本均可读取
- 新分析失败不影响旧成功版本
- 服务重启后的版本和任务恢复
- 两版本指标、结论和建议对比
- 原文件被多个逻辑报告引用时的安全删除
- 报告、版本和产物 API 不泄露绝对路径
- 全量报告不截断数据，只在 UI 首屏折叠展示
- 灵动岛、报告卡片和详情页状态一致
- CSV、XLSX、XLS 及多种亚马逊报告类型

验收场景：用户上传一份报告完成首次分析，在报告库找到它，不重新上传即可再次分析；两次结果均保留、可生成各自 PDF，并可查看明确的版本差异。
