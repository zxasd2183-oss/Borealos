# 亚马逊全量快速分析设计

## 目标

任意亚马逊 CSV/XLS/XLSX 报告都必须读取全部工作表和全部数据行。分析页面应持续显示真实进度，不能因单个大模型请求长时间停在 `1/N`。

## 架构

分析分为两个独立阶段：

1. **本地逐项分析**：解析报告后，对所有有效项目生成结构完整、可复核的诊断。每项都包含数据依据、优先级、原因、后台路径、操作步骤、调整幅度、观察周期、成功标准和回滚条件。该阶段不依赖大模型，必须覆盖 100% 项目。
2. **AI 深度分析与总结**：向大模型发送基于全部数据计算的汇总指标、异常分布、字段画像、优先级统计和代表性异常明细，生成原因解释、整体问题、立即行动、本周行动和持续优化教学。AI 不再逐行生成大量重复文字，但所有数据都参与本地汇总与 AI 输入。AI 超时不能影响逐项结果和 PDF 生成。

已知广告报告使用 PPC 指标规则；未知报告使用字段类型、缺失率、唯一值、数值范围、日期范围和异常值规则，不虚构不存在的广告指标。

## 进度与续跑

任务状态持久化到工作文件，记录：

- `stage`：解析、本地逐项分析、AI 汇总、生成结果、完成
- `processedItems` / `totalItems`
- `startedAt` / `updatedAt`
- `summaryAttempt` 和最近错误

页面每秒更新已处理条数、百分比、当前阶段和耗时。服务重启后，同一任务编号从工作文件恢复；上传文件在任务完成后才删除。AI 汇总失败时，任务仍以“逐项分析完成、AI 汇总降级”结束。

## 数据与输出

- 页面与 PDF 保留全部项目，不设置前 N 项限制。
- 本地逐项分析结果继续使用现有 `itemAnalyses` 结构，兼容当前页面和 PDF。
- AI 总结继续使用现有 `report` 结构。
- 报告明确显示源数据行数、有效项目数、覆盖率和降级状态。

## 错误处理

- 文件读取失败：保留失败文件并显示完整异常尾部。
- 本地规则异常：记录具体项目编号，其他项目继续处理，最终显示覆盖率。
- AI 超时或 JSON 无效：最多重试一次；失败后使用本地汇总，不阻塞完成。
- 页面轮询遇到服务重启：服务从持久化状态恢复，不要求重新上传。

## 验证

使用当前真实搜索词报告验证：

- 3,703 个源数据行全部读取。
- 3,229 个有效搜索词全部生成逐项诊断。
- 18 个广告活动保留。
- 本地阶段在可接受时间内完成且进度持续递增。
- 模拟 AI 超时后仍能完成任务、打开完整页面并生成 PDF。
- 重启服务后原任务编号可继续轮询。
