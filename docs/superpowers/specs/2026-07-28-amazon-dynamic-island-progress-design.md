# 亚马逊全量分析接入灵动岛设计

## 目标

亚马逊报告分析必须同时在页面内和灵动岛展示同一份真实任务状态。用户切换页面或刷新后，仍能看到后台任务的当前阶段、逐项数量和百分比；不得使用模拟进度。

## 状态映射

| 后台阶段 | 灵动岛显示 | 百分比 |
| --- | --- | --- |
| queued | 亚马逊分析排队中 | 0% |
| parsing | 正在读取报告 | 后台返回值 |
| local-analysis | 正在逐项分析 X/Y | 后台返回值 |
| ai-summary | 正在生成 AI 汇总 | 最高 99% |
| pdf | 正在生成完整 PDF | 最高 99% |
| complete/done | 亚马逊报告已完成 | 100%，随后绿闪并移除 |
| error | 亚马逊分析失败 | 红色失败提示并移除 |

## 前端接入

1. 用户点击“开始分析”后调用 `islTaskStart("amazon", "📊", "亚马逊分析")`。
2. 每次收到 `/api/amazon/analyze-status` 的真实状态后：
   - 更新页面内进度；
   - 用同一状态调用 `islTaskProgress`；
   - 名称包含当前阶段或 `processedItems/totalItems`。
3. 任务完成时调用 `islTaskDone`；失败时调用 `islTaskFail`。
4. 页面请求失败但后台任务仍可能运行时，不把任务标为失败；保留岛上任务并交给后台恢复轮询。

## 刷新恢复

灵动岛统一轮询加入亚马逊后台任务状态。服务端提供当前用户正在运行的亚马逊任务列表；前端把它合并为一个 `amazon` 任务：

- 有一个或多个运行任务时，显示最新活动任务；
- 使用后台真实百分比；
- 后台确认任务结束后移除；
- 仅对灵动岛轮询自行发现的任务补播完成提示，避免和页面本地钩子重复。

## 错误与边界

- 百分比限制在 0–100。
- AI 汇总和 PDF 阶段在最终完成前不得显示 100%。
- `totalItems` 未知时显示不确定进度，不伪造百分比。
- 401/会话失效沿用灵动岛现有隐藏逻辑。
- 网络短暂失败不清除已有任务；下次成功轮询恢复。
- 多个亚马逊任务不并排占满灵动岛，聚合为单项并显示最近任务。

## 测试

1. 静态接线测试：开始、进度、完成和失败钩子均存在。
2. 状态映射测试：逐项分析使用真实百分比，AI/PDF 不提前到 100%。
3. 恢复测试：灵动岛轮询包含亚马逊任务接口和合并逻辑。
4. 回归测试：现有视频、动画、表情包和工程任务映射不变。
5. 浏览器验收：开始分析后岛上出现任务；进度更新；刷新后恢复；完成后绿闪。

## 非目标

- 不建设新的通用任务中心。
- 不改变亚马逊分析算法或 PDF 内容。
- 不为已完成历史报告常驻显示进度。
