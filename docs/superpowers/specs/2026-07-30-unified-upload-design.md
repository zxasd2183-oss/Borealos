# Borealos 统一上传与语音提取交付设计

## 目标

所有功能只使用一个上传底座。界面必须显示服务器已确认的真实字节进度；上传完成后，各业务仅接收受控文件 ID，不接触任意磁盘路径。

视频说话声提取只有在真实本地工作进程已启动、真实视频端到端跑通并能下载产物后，才标记为可用。

## 统一上传底座

- 一个浏览器客户端：自动选择普通上传或 2MB 分片上传。
- 一个服务端会话协议：开始、写入分片、完成、取消、恢复查询。
- 一个上传队列：最多三个并行槽位，支持取消和可重试网络错误。
- 一个状态模型：排队、上传中、服务器保存中、完成、失败、取消。
- 进度只采用服务端确认字节数，不模拟百分比。
- 每个业务通过 `purpose` 声明用途；服务端按用途实施扩展名、MIME、大小和数量限制。
- 完成响应只返回上传 ID、文件名、大小、哈希和安全元数据，不返回绝对路径。

## 业务接入

图片翻译、图片换模特、视频、亚马逊报告、反馈附件及其他上传入口全部迁移到统一客户端。旧业务上传接口在迁移期间只作为兼容适配层，最终不得保留独立传输实现。

语音提取使用 `purpose=speech-extraction`，允许受支持的音视频格式和最大 512MB 文件。完成后，上传注册器将统一上传 ID绑定到当前用户的语音任务空间。

## 语音本地工作进程

- 生产服务启动时同时启动受监督的语音工作进程。
- 任务按真实阶段更新：媒体探测、提取音轨、人声处理、转写、说话人区分、字幕、摘要、最终校验。
- 缺少本地依赖时，入口直接显示不可用原因，不允许创建永远排队的任务。
- 每个阶段写入真实工作单位；只有产物存在且通过校验才能达到 100%。
- 失败信息固定显示在进度卡片，并允许安全重试。

## 模型与 API 调配

- 语音链路按能力选择模型，不绑定单一供应商：转写、说话人区分、人声增强、摘要和质量评估分别声明所需能力。
- 管理端维护供应商、API 地址、加密密钥、可用模型、主模型、分类次模型、优先级、回退顺序、预算及健康状态。
- 客户端提供两种来源：使用管理端配置；使用用户自己的 API。用户 API 仅保存在其受保护配置范围内，不在日志和任务结果中返回明文。
- 管理端策略负责根据能力、健康状态和预算选择候选模型；某个模型失败时只按已配置顺序回退。
- 已开始产生流式输出或可能计费后，不允许静默切换供应商。
- 本地模型可作为零云端费用的一个供应商；本机缺少模型运行环境时必须明确显示不可用，不能伪装成处理中。
- 云端调用在执行前展示供应商、模型、预计费用、内容披露范围和硬上限，只有用户明确授权后才执行。
- 管理端支持新增、测试、禁用和轮换 API 密钥；测试连接不得执行收费生成任务。

## 安全与费用

- 默认只执行本地步骤，不调用收费服务。
- 云端模型必须经过现有费用估算和显式授权门。
- 上传 ID按用户隔离，服务端拒绝路径穿越、跨用户引用、超限文件和不支持格式。
- 取消和过期会话清理临时分片；已完成业务文件遵循现有保留策略，不做永久删除。

## 验收

1. 单元测试覆盖分片重试、取消、恢复、限额、用途隔离和跨用户拒绝。
2. 每个业务入口静态检查，禁止新增直接整文件上传代码。
3. 使用真实视频验证上传百分比单调增加且来自服务器确认字节。
4. 重启生产服务后，语音工作进程自动恢复队列。
5. 真实视频端到端生成至少净化人声、文字稿和一种字幕，并通过下载校验。
6. 页面可见验收确认排队、上传、处理、失败和完成状态均清晰可见。
7. 验证管理端主模型、分类次模型和回退顺序能驱动语音各阶段，且所有响应与日志不泄漏密钥。
8. 验证客户端可在管理端配置与用户自带 API 之间切换，切换结果写入任务审计。
