# Borealos 全局任务中心与灵动岛设计

## 目标

Borealos 的所有耗时操作必须进入统一、可恢复、按用户隔离的任务中心。页面内进度、灵动岛、刷新后的恢复状态和跨设备查看必须来自同一份服务端真实状态，不得使用与后台无关的模拟百分比。

## 范围

首轮必须盘点并接入现有全部耗时功能：

- 工程任务与 AI 对话工具调用
- 视频生成、参考视频分析与复刻
- AI 画室、自由图生图、抠图、换装、二次元、图片改字
- 图片翻译、电商图、矢量转换
- 表情包、真动画、GIF
- IP 角色、公众号文章
- 店铺设计、竞店分析
- 亚马逊全量分析与 PDF
- Borealos 视频说话声提取

新增耗时功能必须通过统一任务接口注册，不能再直接为灵动岛编写独立状态逻辑。

## 核心模型

每个任务保存以下字段：

- `id`：不可变任务 ID。
- `userId`：所属用户，所有查询强制隔离。
- `kind`：稳定的任务类型代码。
- `title`：非技术名称。
- `icon`：灵动岛图标。
- `status`：`queued | running | paused | succeeded | failed | cancelled`。
- `stageCode` 与 `stageLabel`：真实后台阶段。
- `progressMode`：`determinate | indeterminate`。
- `progress`：已知时为 0–100，未知时为 `null`。
- `processedItems`、`totalItems`：批量任务的真实数量。
- `priority`：决定灵动岛主任务顺序。
- `createdAt`、`startedAt`、`updatedAt`、`finishedAt`。
- `errorCode`、`errorMessage`：失败时可供用户理解和重试。
- `resourceRef`：原业务任务 ID，不暴露本机路径或密钥。
- `canPause`、`canResume`、`canRetry`、`canCancel`。

服务端是状态真源。前端只能展示服务端状态或在请求刚提交、尚未取得任务 ID 时显示“正在提交”，不得自行推进百分比。

## 服务端组件

### Task Registry

负责创建、更新、查询和终结任务。更新必须保证：

- 状态转换合法；
- 进度不越界；
- 未完成任务不得达到 100%；
- 已知总量时按真实完成量计算；
- 更新写入原子持久化文件，服务重启后可恢复。

### Task Adapter

每种旧功能提供一个小型适配器，把原有 job/task 状态转换为统一任务模型。适配器不得改变原业务算法。没有真实百分比的同步操作使用 `indeterminate`，只报告真实阶段。

### Active Task API

- `GET /api/task-center/active`：当前用户的排队、运行、暂停任务。
- `GET /api/task-center/recent`：最近完成和失败任务。
- `GET /api/task-center/:id`：单项详情。
- `POST /api/task-center/:id/pause`
- `POST /api/task-center/:id/resume`
- `POST /api/task-center/:id/retry`
- `POST /api/task-center/:id/cancel`

控制接口只在对应任务明确声明能力时开放，并继续调用原业务实现。

## 灵动岛行为

### 收起态

- 无任务：显示现有待机状态。
- 一个任务：显示图标、任务名、阶段和真实百分比；未知百分比显示呼吸进度，不显示数字。
- 多个任务：显示最高优先级且最近更新的任务，并显示“另有 N 项”。

### 展开态

显示全部活动任务，每项包含阶段、真实进度、数量和可用控制。排序规则为：

1. 失败且等待处理；
2. 正在运行；
3. 已暂停；
4. 排队中；
5. 同类中按优先级和更新时间。

### 完成与失败

- 成功：100%，绿色完成反馈，然后移入最近任务。
- 失败：红色反馈并保留重试入口，不自动伪装为完成。
- 网络短暂失败：保留上次已知状态，标记“正在重新连接”，不得删除任务。

## 页面联动

页面组件和灵动岛订阅同一个前端任务存储。用户在任意页面启动任务后：

1. 接口返回统一 `taskId`；
2. 任务中心轮询活动任务；
3. 灵动岛和发起页面同时更新；
4. 切换页面、刷新或换设备后由服务端恢复；
5. 成功或失败后，原页面读取 `resourceRef` 对应结果。

前端保留旧页面的详细业务进度，但数据来源改为统一任务模型。旧的 `islTaskStart/Progress/Done/Fail` 仅作为兼容层，最终转发到统一任务存储，不再成为状态真源。

## 迁移顺序

1. 建立任务模型、持久化、API 和前端统一存储。
2. 接入已有后台异步任务：视频、表情包、真动画、文章、店铺、亚马逊、参考视频和工程任务。
3. 接入同步耗时工具：图像生成与编辑、电商、翻译、矢量、GIF、竞店分析。
4. 接入 Borealos 视频说话声提取。
5. 删除重复轮询和模拟进度，保留必要兼容层。

每一批迁移完成后都必须可独立部署，不能等待全部功能后一次性上线。

## 错误、安全与隐私

- 所有接口必须验证登录用户与任务所属关系。
- API 不返回密钥、原始凭据、本机绝对路径或其他用户信息。
- 服务重启时恢复 `queued/running/paused`；无法确认仍运行的任务标记为可恢复，而不是直接成功。
- 重试创建新尝试记录并保留原失败信息，避免覆盖审计证据。
- 取消和暂停属于外部状态变更，只有原业务支持时才允许。

## 测试与验收

### 单元测试

- 状态转换、进度边界、未知进度和批量数量计算。
- 多用户隔离。
- 主任务排序与多任务计数。
- 服务重启后的恢复。

### 适配器测试

为范围中的每种任务验证 queued、running、paused（适用时）、succeeded、failed 映射。同步任务必须验证使用不确定进度且不伪造百分比。

### 集成测试

- 同一用户并行启动至少三个不同功能。
- 灵动岛显示主任务及“另有 N 项”，展开后全部可见。
- 刷新页面和重启服务后任务状态恢复。
- 任务完成、失败、断网重连和重试均与原页面一致。
- 两个用户互相看不到任务。

### 生产验收

逐项启动范围内每个可安全测试的功能，保存任务中心和页面的状态证据。涉及云端费用的任务在测试前使用最低成本样本并遵守现有费用确认规则。

## 非目标

- 不改变各功能的生成算法和产物内容。
- 不为没有真实数据的阶段编造百分比。
- 不在本阶段增加新的收费方式。
- 不把其他独立项目的任务混入 Borealos 用户任务中心。
